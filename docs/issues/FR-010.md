# [FR-010] Electron Shell and Shared React Navigation

## Labels
`MUS`, `shell`, `ux`

## User Story

As a builder, I want a polished Electron shell and shared React navigation model with project rails, session tabs, inspectors, and responsive layouts so that the workflow feels clear and fast on desktop and coherent in the browser.

## Proposed Solution

### Overview

Build a shared React shell that mounts in Electron and in the browser, with Electron adding native powers through typed preload IPC instead of a separate UI stack.

### Implementation Flow

1. Define shared shell layout and navigation primitives.
2. Build desktop and browser mounts for the same renderer.
3. Bind runtime, branch, workspace, and capability state into the header, rails, and inspector.

### Key Considerations

- The desktop shell should feel premium without diverging from the browser experience.
- Information density must remain readable across wide desktop layouts and narrower browser states.

## Acceptance Criteria

- [ ] Users can navigate projects, sessions, and inspectors without losing context.
- [ ] The shell exposes branch, workspace, runtime, and shell capability state in primary UI surfaces.
- [ ] The shared renderer is visually aligned with the approved design direction.
