# [FR-014] Shared Design System and Browser-Compatible UI Flow

## Labels
`MUS`, `design`, `ux`

## User Story

As a builder, I want the desktop shell and browser build to share one design system and interaction model so that the product feels like one platform and the UX can be refined before implementation hardens.

## Proposed Solution

### Overview

Use a shared design system, browser-reviewable prototypes, and an explicit design review loop before feature implementation locks the UI.

### Implementation Flow

1. Produce browser-reviewable prototypes for the core surfaces.
2. Review the prototypes for desktop and browser capability differences.
3. Require approval before implementation moves into feature hardening.

### Key Considerations

- Prototype coverage must include the key orchestration and streaming surfaces.
- Design revisions should update the same source-of-truth artifacts used by both shells.

## Acceptance Criteria

- [ ] Reviewable prototypes exist for the required shared shell surfaces.
- [ ] Design review produces explicit refinement notes for desktop and browser delivery.
- [ ] Build work does not begin before mockup approval.
